## Working

### Platform

- Client changes reuse transport contracts and preserve server-side access boundaries

### Company collaboration

- Companies share Projects without silently assigning ownership or expanding access
- An exiting Company keeps only its permitted frozen Project history
- Project navigation keeps represented context and offers explicit recovery states

### Conversation

- Retrying a message or attachment does not duplicate completed work
- Thread unread state reflects messages the represented participant actually viewed
- People can reach older conversation and the context around referenced messages
- Unsent text stays with its conversation when people navigate or retry
- Private image attachments can render sized previews without discarding the original
- Project search uses deliberate query timing and a keyboard-accessible dialog

### Tasks

- Tasks retain workflow, ownership, and accessible conversation context
- A realtime update does not erase an unsaved task edit
- Repeating a task-create submission retains one creation intent
- Web and mobile apply the same task-move rules
- Boards, lists, and task details load the work being viewed rather than the whole
  Project

### Assistant

- Imported memory remains scoped to the Project or Channel that owns it
- Assistant work exposes progress, deadlines, and a retry path

### Verification and release

- Changes are checked for types, tests, dependency risk, and new architecture violations
